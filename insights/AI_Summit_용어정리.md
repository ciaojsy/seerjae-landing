# AI Summit 용어 정리

> AI Summit 글을 작성하며 정리한 제품 검증, 계약, 매출, 가격, 투자, 기술 및 데이터 관련 용어입니다.

---

## 1. 제품 검증 단계

### Demo — 데모

**질문:** 제품이 어떻게 보이고 작동하는가?  
**결과물:** 기능 시연

데모는 제품을 보여주는 자리입니다. 고객 환경에서 사업적 가치를 입증하는 단계는 아닙니다.

### PoC — Proof of Concept, 개념 증명

**질문:** 기술적으로 가능한가?  
**결과물:** 핵심 기술, 데이터 연동 또는 가설의 가능성 확인

### PoV — Proof of Value, 가치 증명

**질문:** 고객이 돈을 낼 가치가 있는가?  
**결과물:** 고객의 실제 수치로 내리는 구매 및 투자 판단

PoV의 결과물은 데모 화면이 아니라 다음 중 하나를 선택할 수 있는 증거입니다.

- **GO:** 합의한 기준을 충족했으므로 본구축으로 진행
- **보완 / ITERATE:** 가능성은 확인했지만 조건을 보완해 다시 검증
- **STOP:** 해당 업무에는 맞지 않으므로 추가 투자 중단

### Pilot — 파일럿

**질문:** 제한된 실제 환경에서 운영할 수 있는가?  
**결과물:** 한정된 업무, 데이터, 사용자 범위에서의 시험 운영

파일럿은 실행 범위를 뜻합니다. 하나의 파일럿 안에서 PoC와 PoV를 함께 진행할 수도 있습니다.

### MVP — Minimum Viable Product, 최소기능제품

**질문:** 최소 기능으로 실제 사용과 학습을 시작할 수 있는가?  
**결과물:** 반복 사용이 가능한 초기 제품과 사용자 피드백

MVP는 회사가 시장 학습을 시작하기 위한 최소 제품이고, 파일럿은 특정 고객 환경에서 제한적으로 운영하는 방식입니다.

### Full deployment — 본구축

**질문:** 조직 전체의 운영·보안·책임 요건을 충족하는가?  
**결과물:** 권한, 예외 처리, 보안, 지원 체계를 포함한 정식 도입

### 용어 사용 원칙

데모, PoC, PoV, 파일럿은 업계와 고객사마다 혼용됩니다. 계약서에는 명칭만 쓰지 말고 다음을 명시합니다.

- 대상 업무와 범위
- 기간
- 제공 데이터
- 담당자와 권한
- 성공 기준
- 종료 후 GO / 보완 / STOP 조건
- 유료 전환 조건

## 2. 계약과 매출 상태

다음 네 단계는 서로 같지 않습니다.

> `selected ≠ contracted ≠ paid ≠ revenue`

| 상태 | 한국어 | 의미 |
|---|---|---|
| selected | 선정됨 | 지원사업, 프로그램 또는 파일럿 대상으로 뽑힘 |
| contracted | 계약됨 | 고객과 계약을 체결함 |
| paid | 대금을 받음 | 고객의 지급이 완료됨 |
| revenue | 매출로 인식됨 | 회계기준에 따라 수익으로 기록됨 |

### 작성 원칙

- 선정 실적을 계약 실적으로 표현하지 않습니다.
- 계약 금액과 실제 입금액을 구분합니다.
- 입금액과 회계상 매출을 구분합니다.
- 계약 기간 전체 금액과 ACV를 구분합니다.
- 아직 매출이 없다면 숨기지 않고, 파일럿·계약 논의·고객 반응 등 현재 확보한 증거를 구체적으로 밝힙니다.

## 3. 영업과 계약 용어

| 용어 | 권장 한국어 | 쉬운 설명 |
|---|---|---|
| B2B | 기업 간 거래 | 기업을 고객으로 삼는 사업 |
| IR | 투자설명 | 사업성과 성장 가능성을 투자자에게 설명하는 활동 |
| pitch deck | IR 자료 / 피치 자료 | 투자자나 고객을 설득하기 위한 발표 자료 |
| traction | 고객 사용·지불의 증거 | 고객이 실제로 사용, 계약 또는 결제하고 있다는 신호 |
| internal champion | 내부 전도사 | 고객사 안에서 도입을 대신 설득해 주는 사람 |
| unfair advantage | 남들은 갖지 못한 나만의 강점 | 경력, 관계, 전문성 등 쉽게 복제하기 어려운 출발점 |
| design partner | 디자인 파트너 | 초기 제품을 함께 시험하고 개선하는 고객 |
| enterprise contract | 엔터프라이즈 계약 | 기업·기관과 맺는 비교적 큰 규모의 소프트웨어 계약 |
| NDA | 비밀유지계약 | 공유한 기밀정보를 외부에 공개하지 않기로 한 계약 |
| ACV | 연간 계약 금액 | 하나의 계약에서 1년 동안 발생하는 계약 금액 |
| pre-revenue | 매출 발생 전 | 아직 회계상 매출이 발생하지 않은 상태 |
| Q&A | 질의응답 | 발표 후 질문과 답변 |

### LOI — Letter of Intent

본문에서는 이해를 돕기 위해 **유료 전환 서약서**로 설명했습니다. 다만 모든 LOI가 법적으로 구매를 강제하는 것은 아닙니다.

더 정확한 정의:

> 유료 전환 의향과 조건을 담은 문서이며, 법적 구속력은 계약 조항에 따라 달라집니다.

## 4. 가격과 수익 구조

| 용어 | 권장 한국어 | 의미 |
|---|---|---|
| tiered packaging | 단계별 패키지 / 티어드 패키징 | Lite·Standard·Enterprise처럼 기능과 범위별로 상품을 나누는 방식 |
| pricing tier | 가격 단계 / 요금제 등급 | 고객 규모와 요구 수준에 따른 가격 구간 |
| upgrade path | 상위 단계로 확장하는 경로 | 사용 범위와 성과에 따라 상위 요금제로 이동하는 구조 |
| implementation fee | 구축비 | 초기 설치, 설정, 통합에 받는 일회성 비용 |
| integration fee | 통합 비용 | 고객 시스템이나 장비와 연결하는 비용 |
| annual license | 연간 라이선스 | 제품 사용권에 대해 매년 받는 비용 |
| recurring revenue | 반복 매출 | 라이선스나 구독처럼 반복해서 발생하는 매출 |
| one-time revenue | 일회성 매출 | 구축이나 통합처럼 한 번 발생하는 매출 |
| per-asset pricing | 자산·대수 기반 과금 | 장비나 관리 대상의 수에 비례한 과금 |
| lifetime deal | 평생 이용 계약 | 한 번의 결제로 장기간 이용권을 제공하는 초기 고객 상품 |
| fixed price | 고정 단가 | 사용량과 관계없이 미리 정한 가격 |

### 권장 가격 구조

> 검증 → 본구축 → 반복 라이선스

가격이 완벽해질 때까지 기다릴 필요는 없습니다. 고객이 “얼마예요?”라고 물었을 때 바로 답할 수 있도록 세 단계의 가격을 먼저 정합니다. 그리고 다음을 분명히 구분합니다.

- 어떤 단계가 일회성 매출인가
- 어디서부터 반복 매출이 발생하는가
- 사용량, 모듈 수, 장비 수가 늘면 가격이 어떻게 확장되는가

## 5. SI와 제품 사업의 구분

| 구분 | SI / 구축 대행 | 반복 라이선스 제품 |
|---|---|---|
| 제공 가치 | 고객별 개발과 통합 | 재사용 가능한 제품 사용권 |
| 매출 성격 | 프로젝트성·일회성 | 갱신되는 반복 매출 |
| 확장 방식 | 매출 증가에 인력 증가가 동반되기 쉬움 | 사용자·모듈·자산 증가로 확장 가능 |
| 핵심 증거 | 납기와 프로젝트 이익률 | 갱신률, 반복매출, 재사용률 |
| 제품성 판단 | 고객마다 새로 만드는 비중 | 두 번째 고객에게 그대로 재사용하는 비중 |

제품성을 보여주는 대표 문장:

> 동일 업종 두 번째 고객의 재사용률 X%, 도입 소요 Y일

또는:

> 두 번째 고객에게는 이미 만들어 둔 것을 그대로 다시 씁니다. 새로 만드는 일이 줄어들기 때문에 매출이 두 배가 되어도 인력이 두 배로 늘지 않습니다.

SI 자체를 가치가 낮은 사업으로 단정하지는 않습니다. 핵심은 **반복 가능성, 재사용률, 이익률과 인력 의존도**입니다.

## 6. 투자 지표

| 용어 | 의미 |
|---|---|
| Gross margin | 매출에서 제품·서비스 제공에 직접 든 비용을 제외하고 남는 비율 |
| LTV | 고객 한 곳이 거래 기간 전체에 걸쳐 남길 것으로 예상되는 경제적 가치 |
| CAC | 신규 고객 한 곳을 확보하는 데 사용한 영업·마케팅 비용 |
| LTV/CAC | 고객 가치가 고객 확보 비용의 몇 배인지 나타내는 비율 |
| CAC payback period | 고객 확보 비용을 매출총이익으로 회수하는 데 걸리는 기간 |
| burn | 일정 기간 회사가 소진한 순현금 |
| burn efficiency | 사용한 현금으로 얼마나 효율적으로 성장과 반복매출을 만들었는지 보는 개념 |
| burn multiple | 순현금 소진액을 신규 순 ARR 증가분으로 나눈 지표 |
| runway | 현재 보유 현금으로 사업을 지속할 수 있는 예상 기간 |
| valuation | 투자자가 평가한 기업가치 |

### 핵심 문장

> AI 기술이 뛰어나도 사업의 평가 기준은 달라지지 않습니다. 투자자는 고객을 확보하는 데 얼마를 쓰고, 그 고객에게서 얼마를 벌며, 투자한 비용을 얼마나 빨리 회수하는지를 봅니다.

`burn efficiency`는 정의가 여러 가지이므로 가능하면 산식을 함께 적습니다.

> Burn multiple = 순현금 소진액 ÷ 신규 순 ARR

## 7. 기술과 데이터 용어

| 용어 | 권장 한국어 | 쉬운 설명 |
|---|---|---|
| baseline | 기준선 | 도입 전 시간·비용·품질을 비교하기 위한 출발값 |
| prediction horizon | 예측 구간 / 예측 선행기간 | 사건 발생보다 얼마나 먼저 예측하는지 나타내는 기간 |
| longitudinal data | 종단 데이터 | 같은 대상의 변화를 장기간 반복 측정한 데이터 |
| biobank | 바이오뱅크 | 연구용 생체시료와 관련 데이터를 보관한 자원 |
| real-world data | 실환경 데이터 | 실제 운영·진료·사용 과정에서 생성된 데이터 |
| data flywheel | 데이터 플라이휠 | 사용 증가가 데이터와 제품 개선으로 이어지고, 개선된 제품이 다시 사용을 늘리는 구조 |
| closed loop | 폐루프 / 닫힌 피드백 순환 | 실행 결과가 다시 입력으로 돌아가 다음 판단과 개선에 반영되는 구조 |
| audit trail | 감사기록 | 누가 언제 무엇을 근거로 판단하고 승인했는지 추적하는 기록 |
| human intervention | 사람의 개입 | 자동 처리 과정에서 사람이 검토, 승인 또는 수정하는 절차 |
| BOM | 자재명세서 | 제품 생산에 필요한 부품과 수량의 목록 |
| API | 응용프로그램 인터페이스 | 소프트웨어가 기능과 데이터를 주고받는 연결 규칙 |
| GPU | 그래픽처리장치 | AI 학습과 추론에 사용하는 병렬 계산 장치 |
| ECG | 심전도 | 심장의 전기적 활동을 기록한 신호 |
| SARC-F | 근감소증 선별 설문 | 근력, 보행, 계단, 낙상 등을 묻는 선별 도구 |

### Closed loop 표현 원칙

단순히 데이터가 쌓이는 것만으로는 closed loop가 아닙니다. 결과를 확인하고 다시 다음 판단과 개선에 반영해야 합니다.

권장 흐름:

> 감지 → 진단 → 예측 → 보정 → 검증

또는:

> 수집 → 실환경 데이터 → 배포 → 학습·처리 → 결과 확인 → 다시 수집

## 8. AUC와 AUROC

### AUC

곡선 아래 면적을 뜻합니다. 분류 모델 문맥에서는 일반적으로 ROC 곡선 아래 면적을 의미하지만, 정확성을 위해 가능하면 어떤 곡선인지 밝힙니다.

### AUROC

분류 임계값 전체에서 모델이 위험한 사례를 안전한 사례보다 얼마나 잘 구분하는지 나타내는 값입니다.

쉽게 설명하면:

> 위험한 쪽과 안전한 쪽의 순서를 얼마나 잘 가려내는지를 0에서 1 사이로 나타낸 점수

주의할 점:

- `0.5`는 무작위 분류 수준입니다.
- `0.9 이상`을 매우 우수하다고 보는 것은 일반적인 경험칙이지 절대 기준은 아닙니다.
- 서로 다른 데이터셋, 표본, 예측 기간에서 얻은 AUC를 단순 비교하면 안 됩니다.
- 외부 검증, 신뢰구간, 민감도와 특이도를 함께 확인해야 합니다.
- `0.607은 사실상 찍는 수준`이라는 표현은 과도할 수 있습니다. 더 정확한 표현은 `무작위 수준인 0.5에 비교적 가까운 판별력`입니다.

## 9. 해자와 진입 장벽

### Moat — 해자

경쟁사가 쉽게 따라 들어오지 못하게 막는 구조적 장벽입니다.

본문에서 다룬 세 가지:

1. 물리 세계
2. 유통과 네트워크 효과
3. 독점 데이터와 규제

핵심 설명:

> 좋은 모델은 경쟁사도 만들 수 있습니다. 하지만 복잡한 규정과 현장 절차를 실제로 해결해 본 경험은 쉽게 복제할 수 없습니다. 규제가 많은 산업의 복잡성은 약점이 아니라 경쟁사를 막아 주는 진입 장벽입니다.

다만 `방어 가능한 해자는 셋뿐`이라는 표현은 발표자의 분류입니다. 일반적으로는 다음 요소도 해자로 볼 수 있습니다.

- 전환 비용
- 브랜드
- 특허
- 운영 노하우
- 규모의 경제
- 독점적인 공급 또는 유통 관계

## 11. 주의가 필요한 표현

### LOI

`LOI`는 일반적으로 `의향서`이며, 반드시 법적 구속력이 있는 유료 전환 계약은 아닙니다. 계약 조항을 확인해야 합니다.

### 선정, NDA, 파일럿

선정, NDA 체결, 파일럿 논의는 관심과 진전의 신호이지만 계약·입금·매출과 동일하지 않습니다.

### SI 배제

SI를 무조건 낮은 가치의 사업으로 표현하지 않습니다. 표준화된 구축 패키지와 제품 전환 경로가 있다면 전략적일 수 있습니다.

### 반복 매출

반복 청구된다고 해서 모두 좋은 반복매출은 아닙니다. 갱신률, 해지율, 고객 집중도와 매출총이익률을 함께 봐야 합니다.

### LTV/CAC

초기 B2B 기업은 고객 수가 적어 LTV 추정이 불안정할 수 있습니다. 매출 기준인지 매출총이익 기준인지, CAC에 영업 인건비가 포함되었는지 명시합니다.

### 데이터 플라이휠

데이터가 늘어난다는 사실만으로 성능 향상이 보장되지는 않습니다. 피드백 품질, 고객 동의, 보안과 재학습 검증이 필요합니다.

### AI기본법

법적 의무를 단정할 때는 적용 대상과 구체적인 의무를 현행 법령, 시행령 및 공식 가이드라인에서 확인합니다. 발표자의 발언은 발표자의 견해임을 구분합니다.

### 투자 및 시장 수치

투자금, 비율과 환산 금액에는 기간, 집계기관, 환율과 출처를 함께 적습니다. 발표자료의 수치는 실사로 검증된 값과 구분합니다.

### 인용문

현장 발언을 축약하거나 번역했다면 직접 인용과 필자의 요약을 구분합니다. 필요하면 발표 취지, 필자 번역이라고 표시합니다.
